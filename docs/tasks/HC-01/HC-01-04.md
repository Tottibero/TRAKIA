# HC-01-04 — Calidad, pruebas arquitectónicas y CI

## Identificación

- **Bloque:** HC-01 — Infraestructura
- **Estado:** completada
- **Rama:** `chore/hc-01-infrastructure`

## Especificación aprobada

### Objetivo

Establecer controles reproducibles de lint, formato, tipos, pruebas y compilación para el monorepo, localmente y en GitHub Actions, además de comprobar automáticamente las restricciones arquitectónicas objetivas de ADR-015.

### Alcance

Configurar ESLint para API NestJS/TypeScript, web Vue/TypeScript y contracts; Prettier con `format:check` y `format`; reglas arquitectónicas y matriz de cobertura de las 17 reglas ARCH; comandos raíz para lint, formato, typecheck, unitarias, integración, arquitectura, build y `check`. Separar las unitarias de la integración PostgreSQL 17, exigir `TRAKIA_TEST_DATABASE_URL`, ejecutar migraciones antes de integración y mantener la base aislada sin acciones destructivas. Crear `.github/workflows/ci.yml` con job `quality`, para PR hacia `main` y push a `main`, usando Node/pnpm fijados, lockfile y PostgreSQL temporal. Documentar controles, límites y resultados.

### Exclusiones

Autenticación, entrenamiento, refactorizaciones extensas, migración de frameworks de testing, despliegue, protección remota de GitHub, servicios externos de análisis y hooks Git obligatorios. No modificar entidades deportivas ni el entorno Docker.

### Dependencias

HC-01-03b, HC-01-03e, HC-01-03f y HC-01-03g. Aplican ADR-015 y `docs/architecture/module-conventions.md`.

### Archivos o módulos afectados

Configuración raíz de calidad y dependencias; scripts de test API; script de integración; workflow CI; `docs/quality.md`, esta tarea, índice HC-01 y `docs/progress.md`.

### Criterios de aceptación

1. ESLint cubre los tres workspaces relevantes y Prettier verifica sin modificar.
2. Los scripts de calidad se ejecutan desde raíz y `pnpm check` no necesita PostgreSQL.
3. Las unitarias existentes funcionan sin base; ausencia de configuración de integración falla explícitamente.
4. Integración usa PostgreSQL 17 aislado, URL dedicada y migraciones, sin acceder a producción ni destruir la base de desarrollo.
5. La matriz cubre las 17 reglas ARCH y distingue automatización de revisión humana; se detectan límites objetivos y ciclos.
6. CI tiene job `quality`, instalación reproducible, servicio PostgreSQL temporal y falla ante controles obligatorios fallidos.
7. Build y typecheck pasan, Docker Compose y migraciones existentes no cambian.
8. Protección remota de `main` y validación real en Actions quedan pendientes de autorización/publicación.

### Pruebas previstas

`pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm architecture:check`, `pnpm build`, `pnpm check`, `pnpm test:integration`, ausencia de URL, `git diff --check`, revisión de workflow, Docker Compose y migraciones.

## Ejecución y resultados

### Resumen de implementación

Se añadieron lint/format, checks raíz, análisis de dependencias, workflow `quality` y documentación de cobertura ARCH. La prueba HTTP pasó de estar silenciosamente omitida a ser integración obligatoria; el runner autoriza únicamente `trakia_test` local, comprueba la base efectiva antes de migrar y mantiene las unitarias con `node:test`.

HC-01-04b completó los límites automáticos Domain→HTTP y Presentation/controlador→persistencia. `architecture:check` ejecuta fixtures temporales para confirmar que los imports prohibidos fallan y Application/Contracts permitidos pasan.

### Archivos realmente modificados

Configuración raíz ESLint/Prettier/dependency-cruiser y scripts; manifests raíz y API, lockfile; runner de integración; workflow CI; formato puntual de fuentes API/web ya cubiertas; `docs/quality.md`, progreso, índice HC-01 y esta tarea.

HC-01-04b añadió reglas en `eslint.config.mjs` y `.dependency-cruiser.cjs`, fixtures automatizadas en `scripts/architecture-rule-tests.mjs` integradas con `scripts/architecture-check.mjs`, y actualizó la matriz ARCH y estos resultados.

### Pruebas ejecutadas y resultados

**Superadas con Node 26.13.0 y pnpm 12.19.0:** `pnpm check` (lint, formato, typecheck contracts/web/API, arquitectura: 33 módulos/38 dependencias, 16 unitarias sin skips, build), `git diff --check`. HC-01-04a corrigió la precedencia de destino, sanea el entorno y verifica la conexión efectiva con `SELECT current_database()` antes de migrar.

**HC-01-04b:** `pnpm architecture:check` pasó fixtures negativos para `node:http[s]`, `node:http2`, Express/subrutas, clientes HTTP y `fetch` en Domain; y TypeORM, entidades, repositorios o infraestructura desde Presentation/controladores. Pasaron los positivos para Application/Contracts y `node:path`, confirmando que no se prohíbe Node estándar indiscriminadamente. El grafo normal pasó. `pnpm lint` y `pnpm check` pasaron. Las fixtures se crean bajo una ruta temporal del módulo API y se eliminan en `finally`; no persisten en el árbol.

**Integración aislada:** ejecutada en PostgreSQL 17.6 tanto con `POSTGRES_DB`/`PGDATABASE` ausentes como heredando deliberadamente ambos en `trakia_dev`. En ambos casos el verificador consultó y confirmó `current_database() = trakia_test` antes de migrar; el health test pasó (1 pasada, 0 fallidas, 0 omitidas). La migración quedó al día en `trakia_test` (una fila en `typeorm_migrations`). Pruebas negativas confirman que URL ausente y destinos `trakia_dev`, `postgres` y `trakia_prod` fallan antes de invocar comandos de build/migración.

**Fallo esperado confirmado:** `env -u TRAKIA_TEST_DATABASE_URL pnpm test:integration` termina con código 1 y mensaje explícito de configuración requerida.

**Pendiente:** validación del workflow por GitHub Actions después de publicar la rama. No se inició Docker porque PostgreSQL de TRAKIA ya estaba disponible y saludable; los cuatro servicios conservaron su estado.

### Desviaciones justificadas

HC-01-04a modificó `apps/api/src/config/database-config.ts`, `scripts/integration-database.mjs`, `scripts/run-integration-tests.mjs`, `apps/api/test/health.e2e.test.mjs`, y añadió `apps/api/test/integration-database.test.mjs` y `apps/api/test/verify-integration-database.mjs`. `DATABASE_URL` ahora determina la base; el runner solo autoriza `trakia_test` local, limpia `POSTGRES_DB`, `PGDATABASE` y `TRAKIA_DB_DIST`, y comparte el mismo entorno saneado entre verificación, migraciones y servidor HTTP. La verificación TypeORM consulta la base efectiva antes de cualquier migración.

Las reglas bloquean módulos HTTP concretos y clientes HTTP directos en Domain sin prohibir módulos estándar de Node en general. En Presentation/controladores se prohíben rutas internas de infraestructura, TypeORM, entidades y repositorios; Application y Contracts permanecen permitidos. La lógica de delegación del controlador sigue requiriendo revisión humana.

La comprobación de formato de HC-01 requirió aplicar Prettier a un conjunto limitado de fuentes API/web existentes para que `format:check` sea útil desde el primer uso. Se excluyeron documentos y manifiestos `compose.yaml`/`pnpm-workspace.yaml` para evitar cambios ajenos. CI evita recompilar después de `check`.

En la primera ejecución local de HC-01-04 se cargó `.env.docker` completo, incluida `POSTGRES_DB=trakia_dev`. TypeORM priorizaba esa variable sobre el nombre de `DATABASE_URL`: migración y prueba HTTP apuntaron a la base principal. TypeORM creó allí `typeorm_migrations` y añadió el registro de `InitialTechnicalMigration1794355200000`; su método `up()` está vacío. HC-01-04a hace que `DATABASE_URL` determine el destino, elimina variables heredadas y comprueba la base efectiva antes de modificar esquema. No se ejecutó rollback ni se eliminaron datos.

### Incidencias y riesgos pendientes

Una primera ejecución antigua dejó un registro vacío de `InitialTechnicalMigration1794355200000` en `trakia_dev`; su método `up()` no realiza cambios. Se conservó sin rollback para evitar modificar datos existentes. No bloquea el cierre: las ejecuciones posteriores comprobaron el destino efectivo `trakia_test` antes de migrar, y CI utiliza PostgreSQL efímero. El workflow remoto está validado por `quality` en el run `43136334983` para `c625e088d333e99131562ebba91e0bb802f7011a`.
