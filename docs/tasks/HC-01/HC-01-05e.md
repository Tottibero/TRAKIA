# HC-01-05e — Autenticación frontend

## Identificación

- **Bloque:** HC-01 — Infraestructura
- **Estado:** completada
- **Rama:** `chore/hc-01-infrastructure`

## Especificación aprobada

### Objetivo

Ofrecer desde la PWA Vue una experiencia completa de acceso privado mediante la API protegida.

### Alcance

- Crear feature Vue `auth/` organizada según ADR-015.
- Implementar vista de login responsive, optimizada para móvil, con email, contraseña, validación y errores no sensibles.
- Enviar peticiones con cookies y consultar `/api/auth/me` mediante TanStack Query.
- Proteger rutas, mostrar carga al comprobar la sesión inicial y recuperar sesión tras recargar.
- Permitir logout; limpiar estado y caché privada al cerrar sesión o al caducar la sesión.
- Configurar proxy local `/api` en Vite cuando corresponda.
- Evitar caché persistente de respuestas privadas en la PWA.
- No guardar JWT en Pinia, localStorage ni sessionStorage; no duplicar datos remotos entre Pinia y TanStack Query.

### Exclusiones

Registro público, perfiles, recuperación por correo y funcionalidades deportivas.

### Dependencias

HC-01-05d, que completa las protecciones HTTP del backend.

### Archivos o módulos afectados

`apps/web/src/features/auth/`; integración con router, inicialización `app/`, cliente HTTP compartido, configuración Vite/PWA y pruebas frontend. Consumir contratos publicados por `@trakia/contracts` cuando correspondan.

### Criterios de aceptación

1. El formulario permite iniciar sesión y presenta errores sin información sensible.
2. Las rutas privadas no se muestran a usuarios anónimos y presentan estado de carga durante la comprobación inicial.
3. La sesión se recupera tras recargar y logout redirige y limpia datos privados.
4. La expiración del JWT se gestiona y limpia la sesión/caché privada.
5. No se almacena el token en JavaScript ni en almacenamiento persistente del navegador.
6. La interfaz se puede utilizar desde móvil.
7. TanStack Query conserva la propiedad de los datos remotos; Pinia no los duplica.

### Pruebas previstas

Formulario y validaciones, redirecciones, comprobación y recuperación de sesión, expiración, logout y limpieza de caché; flujo integrado frontend/API en configuración local.

## Ejecución y resultados

Autenticación frontend implementada con una feature `auth`, sesión consultada por TanStack Query, rutas protegidas y errores de acceso no sensibles. Las peticiones usan cookies HttpOnly del backend y no almacenan JWT en el navegador. La caché HTTP se desactiva para las respuestas API. La comprobación funcional detectó y permitió corregir una redirección concurrente ante 401.

### Resumen de implementación

Login responsive, recuperación de sesión al iniciar y tras recargar, protección de la ruta privada, logout con limpieza de toda la caché TanStack Query y retorno al login ante respuestas 401. Vite ya tenía proxy `/api`; se conservó y se añadió un alias para importar el punto público de la feature.

`apps/web/src/features/auth/`, `apps/web/src/shared/api/http.ts`, `apps/web/src/app/queryClient.ts`, `apps/web/src/app/createTrakiaApp.ts`, `apps/web/src/App.vue`, `apps/web/src/router/index.ts`, `apps/web/src/views/HomeView.vue`, `apps/web/src/style.css`, `apps/web/tsconfig.json`, `apps/web/vite.config.ts`, `scripts/architecture-check.mjs` y `scripts/architecture-rule-tests.mjs`.

### Desviaciones justificadas

Se añadió el alias `@/` en Vite/TypeScript para importar desde el export público de `features/auth`, ya que las reglas existentes prohíben las rutas relativas de features desde el router y la vista heredada. Para resolver el ciclo, `queryClient` ahora expone un callback de sesión inválida sin importar el router; `createTrakiaApp` compone el callback y conserva el límite de una redirección concurrente. El verificador arquitectónico ahora consume los incumplimientos de `summary.violations` y su fixture confirma que dependency-cruiser rechaza ciclos en el grafo web. Sin cambios a contratos o backend.

### Revisión arquitectónica

- **Resultado:** sin incumplimientos, advertencias ni recomendaciones.
- **`ARCH-ALL-001`:** resuelto. `apps/web/src/app/queryClient.ts` ya no importa el router; publica el callback de sesión inválida y `apps/web/src/app/createTrakiaApp.ts` lo compone con navegación. El router depende del QueryClient en una sola dirección. El verificador procesa `summary.violations`, y el fixture negativo prueba que un ciclo entre módulos web es rechazado.
- **Otras reglas aplicables sin hallazgos:** `ARCH-WEB-001` (shared no depende de features), `ARCH-WEB-002` (router y vista consumen auth por su export público), `ARCH-WEB-003` (las llamadas usan el cliente HTTP compartido), `ARCH-WEB-004` (sin dependencias de entidades API), `ARCH-ALL-002` (contracts y alias usan puntos de import configurados) y `ARCH-ALL-003` (el callback es composición directa, sin bus, store ni capa adicional).
- **Alcance:** revisión independiente del diff disponible de HC-01-05e contra ADR-015 y `module-conventions.md`. La comprobación automatizada registrada en esta ejecución pasó con cero violaciones de dependency-cruiser. No se modificaron código, estado ni aceptación durante esta auditoría.
