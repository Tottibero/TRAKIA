# HC-03-09 — Simplificación de la pantalla Importar plan

## Identificación

- **Bloque:** HC-03
- **Estado:** en revisión
- **Aprobación:** autorizada directamente por el propietario el 2026-11-19; no requiere propuesta ni aprobación visual previa.
- **Naturaleza:** limpieza de interfaz post-MVP; sin cambios a validación o reglas de importación.

## Especificación aprobada

### Objetivo

Reducir el contenido inicial de Importar plan y compactar su disposición móvil, conservando la identidad visual de TRAKIA y el comportamiento del flujo de tres pasos.

### Alcance

- Mantener el título «Importar plan», los pasos Archivo, Revisión y Confirmación, el selector JSON y la acción para continuar.
- Retirar el subtítulo, encabezado «Archivo del plan», ayuda fija sobre validación/tamaño/retención, mensaje inicial «Selecciona un archivo JSON para empezar» y separadores/espacios innecesarios.
- Conservar las validaciones existentes, incluido el máximo de 1 MiB, mostrando sus errores solo cuando correspondan.
- Ajustar el espaciado en la vista existente para una composición compacta y equilibrada en móvil.

### Exclusiones

- Cambiar validaciones, contrato JSON, pasos, flujo de revisión/confirmación, reglas de persistencia, textos de error contextual o identidad visual.
- Rediseñar otras pantallas, añadir componentes compartidos/tokens o cambiar API, contratos y backend.
- Commit, push, pull request o merge.

### Dependencias

- HC-03-07 y HC-03-08 completadas; feature existente `training-plan-imports`.
- `DESIGN.md`, ADR-015 y convenciones actuales del frontend.

### Archivos o módulos afectados

- `apps/web/src/features/training-plan-imports/views/TrainingPlanImportView.vue`.
- Esta ficha, `docs/tasks/HC-03/README.md` y `docs/progress.md`.

### Criterios de aceptación

1. El estado inicial muestra el título, los tres pasos, el selector JSON y el botón para revisar tras elegir un archivo, sin el contenido redundante enumerado en el alcance.
2. Las incidencias de archivo, JSON, documento, servidor y límite de 1 MiB siguen mostrándose con su gestión accesible cuando ocurren; en reposo no aparecen mensajes de error ni validación.
3. La revisión, confirmación, recuperación y navegación siguen funcionando igual.
4. La pantalla mantiene los tokens y la identidad vigente y no desborda horizontalmente en móvil.

### Pruebas previstas

- Pruebas web existentes, typecheck web, lint/formato y auditoría arquitectónica.
- Inspección responsive de la vista compacta si el servidor de desarrollo está disponible.
- `git diff --check`.

## Ejecución y resultados

Se retiraron la explicación inicial, el encabezado repetido, la ayuda fija sobre validación/tamaño/retención y el mensaje de selección inicial. Se eliminaron el separador y los márgenes amplios del estado de archivo y se compactó la cabecera móvil. La lógica de lectura, validación y límite permanece en `useTrainingPlanImport`; los mensajes de error continúan ligados a sus estados correspondientes.
