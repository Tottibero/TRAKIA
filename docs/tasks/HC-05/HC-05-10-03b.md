# HC-05-10-03b — Rediseño visual del ejecutor de entrenamiento

## Identificación

- **Bloque:** HC-05
- **Estado:** completada
- **Tipo:** presentación web del ejecutor online de fuerza individual.

## Especificación aprobada

### Objetivo

Rediseñar directamente en Vue la pantalla principal del ejecutor de fuerza individual con una composición compacta, legible en móvil y coherente con `DESIGN.md`.

### Alcance

- Conservar el recorrido planificación → iniciar sesión → ejecutor del primer ejercicio → iniciar serie, sin preparación ni confirmaciones adicionales.
- Organizar el ejecutor en cabecera del ejercicio/serie, pills de objetivos reales, cronómetro y acciones válidas para el estado deportivo.
- Unificar los colores semánticos de reps, kg y RPE mediante tokens y clases compartidas en planificación, importación, ejecución y resultados.
- Mostrar inicialmente `00:00`, sin iniciar el temporizador y sin ofrecer pausa antes del trabajo/descanso activo.
- Alinear colores, contraste, espaciado, foco y áreas táctiles con los tokens y componentes vigentes de TRAKIA.
- Añadir o ajustar pruebas web y documentar resultados; actualizar índice HC-05 y progreso.

### Exclusiones

- No alterar API, contratos, entidades, migraciones, `workStartedAt`, `activeSeconds`, temporizadores, pausas, recuperación, resultados ni navegación de HC-05-10-03a.
- No rediseñar en profundidad HIIT, AMRAP, circuitos, descansos ni formulario de resultados.
- No añadir librerías, estados persistentes, infraestructura ni inspecciones/capturas de navegador.
- Sin push, PR ni merge.

- ADR-015, `docs/architecture/module-conventions.md` y tokens de `DESIGN.md`.

### Criterios de aceptación

1. La fuerza online presenta ejercicio y serie, objetivos compatibles existentes como pills, cronómetro detenido en `00:00` y una acción «Iniciar serie».
2. No se presenta «Pausar» hasta existir un trabajo o descanso activo; durante trabajo permite terminar y pausar, y durante pausa ofrece reanudar.
3. Se mantienen métricas/unidades, recuperación tras recarga, y semántica de estados deportivos existentes.
4. La superficie usa carbón, blanco cálido y rojo de acción TRAKIA; se adapta a móvil, foco de teclado, texto largo y áreas seguras.
5. No cambia lógica de ejecución, API ni comportamiento de modalidades fuera del alcance visual definido.
6. Pasan `pnpm check`, `pnpm architecture:check`, pruebas web relevantes y `git diff --check`; no se ejecuta integración PostgreSQL salvo razón técnica.
7. Sin revisión visual de navegador por instrucción expresa; se documenta la validación manual pendiente.

### Pruebas previstas

- Acciones de trabajo/pausa, descanso y recuperación tras recarga.

- `pnpm check`, `pnpm architecture:check`, prueba web dirigida y `git diff --check`.

## Ejecución y resultados

### Resumen de implementación

El ejecutor online de fuerza ahora concentra el ejercicio y la serie en una cabecera compacta, representa solo objetivos resueltos y compatibles como pills, y muestra el cronómetro tabular en blanco cálido. El fondo usa carbón, el foco rojo y las acciones principales rojo de TRAKIA. El diseño respeta nombres largos, permite que las pills salten de línea y añade margen de áreas seguras sin imponer una altura fija.

Se normalizaron los pills de métricas en todas las superficies: reps en azul informativo, kg en cian y RPE en ámbar, con el mismo tinte de fondo y color de texto. El mapeo queda registrado como regla y tokens en `DESIGN.md` y `apps/web/src/style.css`; una utilidad compartida resuelve la clase semántica para valores por clave o etiqueta.

La pausa secundaria solo aparece si existe un temporizador de trabajo o descanso; en pausa, «Reanudar» es la acción principal. Se mantiene intacto el flujo online: `Iniciar serie` inicia el temporizador existente y conserva la confirmación transaccional de `workStartedAt`.

### Pruebas ejecutadas y resultados

- **Superado — pruebas web dirigidas:** presentación de métricas, importador, detalle de planificación, resumen final y ejecutor de fuerza (5 archivos).
- **Superado — suite web:** `pnpm check` ejecutó 149 pruebas web satisfactorias; también pasan las 103 pruebas API. La suite cubre fuerza, circuitos, HIIT, AMRAP, descansos y recuperación.
- **Superado — `pnpm check`:** lint, formato, typechecks, fixtures arquitectónicas, dependency-cruiser y encapsulación para 238 módulos, pruebas API/web (149 pruebas web) y builds. Vite conserva el aviso existente de bundle principal superior a 500 kB.
- **Superado — `pnpm architecture:check` independiente:** fixtures, dependency-cruiser y encapsulación para 238 módulos, sin violaciones. El verificador usa la API oficial de Dependency Cruiser dentro del proceso, evitando el subproceso Node que fallaba con `EPERM`.
- **Superado — `git diff --check`** y comprobación Prettier de los archivos afectados (sin errores).
- **Superado — runtime de desarrollo:** tras el error observado al iniciar una serie, se reconstruyó únicamente `api`; Compose informa el contenedor healthy y `GET /api/health` responde `{"status":"ok"}`. No se ejecutaron migraciones ni se tocó PostgreSQL.
- **Superado — detector Impeccable en el primer rediseño:** un aviso de tamaño tipográfico fuera de escala se resolvió usando `text-3xl`, coherente con `DESIGN.md`.
- No se ejecutó integración PostgreSQL ni se inspeccionó o capturó el navegador, según el alcance aprobado.

### Desviaciones justificadas

Se implementa directamente en los componentes productivos por instrucción expresa del propietario, que sustituye para esta tarea el paso genérico de maqueta/propuesta visual. No se realiza inspección visual ni captura de navegador, también por instrucción expresa.

### Incidencias y riesgos pendientes

La validación visual y la repetición manual del inicio de serie tras reconstruir la API quedan pendientes para el propietario; no se inspeccionó el navegador. La ejecución pausada afectada devolvía 409 `WORK_NOT_STARTED` porque su `workStartedAt` persistido era nulo. Por autorización del propietario se borró solo esa fila, que no tenía resultados guardados; se comprobó que ya no existe en `trakia_dev`. El chunk principal de Vite supera 500 kB y genera el aviso existente.

### Revisión arquitectónica

- **Resultado:** sin hallazgos arquitectónicos en el cambio; revisión manual independiente completada.
- **Evidencia:** la vista, pills y presentación de resultados siguen dentro de sus features; `metric-pill-presentation.ts` es una utilidad pura bajo `shared` y no importa features. No se introducen dependencias entre features, contratos, backend ni persistencia. Revisadas ADR-015 y `module-conventions.md`, en particular ARCH-WEB-001/002/004 y ARCH-ALL-001/002/003. `pnpm architecture:check` independiente pasa con 238 módulos.
- **Hallazgos y resolución:** ninguno. Sin recomendaciones arquitectónicas pendientes.

### Revisión y aceptación

- **Resultado:** completada por autorización explícita de commit del propietario.
- **Evidencia de revisión y aprobación:** el propietario autorizó la implementación directa, solicitó el commit, autorizó reconstruir solo la API y borrar la ejecución inconsistente concreta. No se inspeccionó el navegador; la validación visual/manual restante se acepta como pendiente de alcance.
